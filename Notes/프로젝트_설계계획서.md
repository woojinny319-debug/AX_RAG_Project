## 1. 프로젝트 개요

### 1-1. 배경

제약·바이오 산업은 연구개발비 자산화, 기술이전 수익인식, 바이오시밀러 무형자산 처리 등 회계적으로 판단이 복잡한 사항이 집중되어 있다. 이 영역의 회계처리를 검토하기 위해서는 세 가지 정보를 동시에 확인해야 한다.

1. **규범적 기준**: K-IFRS가 해당 거래를 어떻게 정의하는가
2. **실무 관행**: 동종 업계 상장사들이 실제로 어떻게 처리했는가
3. **감사 관점**: 외부감사인이 어떤 위험을 핵심감사사항(KAM)으로 식별했는가

현재 이 세 가지 정보는 각각 K-IFRS 기준서, DART 공시 시스템, 감사보고서에 분산되어 있어 통합적 검색이 불가능하다. 본 시스템은 이 세 소스를 단일 자연어 인터페이스로 통합한다.

### 1-2. 핵심 사용 시나리오

> "제약사의 연구개발비 자산화 요건은 무엇이며, 주요 상장사들은 어떻게 처리하고 있고, 감사인은 이를 왜 핵심감사사항으로 선정하는가?"

이 질문 하나에 대해 시스템은 다음 세 관점의 답변을 구조화하여 제시한다.

| 출력 섹션 | 정보 소스 | 예시 |
|---------|---------|------|
| ① K-IFRS 기준 | K-IFRS PDF RAG | "K-IFRS 1038호 **문단 57**에 따르면, 개발단계 지출은 기술적 실현가능성 등 6가지 요건을 모두 충족할 때 자산으로 인식한다." |
| ② 기업 사례 | DART 사업보고서 주석 | "삼성바이오로직스는 **2024년 사업보고서 주석 3**에서 임상 3상 진입 시점을 자산화 개시 기준으로 명시하고 있다." |
| ③ 감사 관점 | KAM 보고서 RAG | "삼일PwC KAM 보고서는 이 사항이 핵심감사사항인 이유로 경영진의 판단 개입 범위와 추정의 불확실성을 지적한다." |

**커버하는 주요 질의 유형 (KAM 보고서 3대 감사사항 기반)**

- 연구개발비 자산화 기준 및 단계별 판단
- 무형자산(개발비, 기술이전권) 손상 검토
- 기술이전·마일스톤 계약의 수익인식 시점 (K-IFRS 1115호)
- 공정가치 평가 실무고려사항

### 2-2. 설계 원칙

**소스 분리**: K-IFRS(규범), DART(실무), KAM(감사) 세 컬렉션을 분리 관리한다. 성격이 다른 텍스트를 하나의 컬렉션에 묶으면 쿼리 시 컨텍스트가 희석되기 때문이다. 쿼리 단계에서 병렬 조회 후 LLM이 합성한다.

**파이프라인 분리**: 데이터 인제스트(오프라인)와 검색·추론(온라인)을 분리한다. DART 데이터는 사전에 수집·가공해 ChromaDB에 저장하고 앱 실행 시에는 검색만 수행한다. 이는 데모 안정성과 함께 프로덕션 아키텍처의 표준 패턴이기도 하다.

**출처 명시**: 모든 답변에 "K-IFRS 1038호 문단 57", "삼성바이오로직스 2024 사업보고서 주석 3"처럼 검증 가능한 출처를 포함한다. 회계 정보에서 신뢰성은 인용 가능성에서 온다.

## 4. 데이터 파이프라인

### 4-1. K-IFRS 인제스트 (오프라인, 최초 1회)

```
K-IFRS PDF 파일
    → PyMuPDF 텍스트 추출
    → 조항(문단) 단위 청킹
       - 청킹 전략: "문단 N" 패턴 기반 경계 인식
       - chunk_size ≈ 500 tokens, overlap = 50 tokens
    → 메타데이터 태깅: {source: "K-IFRS_1038", paragraph: "57"}
    → ChromaDB 'kifrs' 컬렉션 저장
```

**대상 문서**

| 문서 | 주요 커버 주제 |
|------|-------------|
| K-IFRS 제1038호 — 무형자산 | 개발비 자산화 요건, 상각, 손상 |
| K-IFRS 제1115호 — 수익 | 기술이전·마일스톤 수익인식, 수행의무 |
| K-IFRS 제2032호 — 웹사이트 원가 | 무형자산 세부 적용 지침 |

### 4-2. KAM 인제스트 (오프라인, 최초 1회)

```
삼일PwC 제약·바이오 KAM 보고서 PDF (30페이지)
    → PyMuPDF 텍스트 추출
    → 섹션 단위 청킹 (목차 구조 기반)
       - 섹션: 연구개발비 / 무형자산 / 매출인식·Cut-off / 공정가치 평가
```

## 5. 핵심 기술 구현

### 5-1. Hybrid Search (`rag_engine.py`)

순수 의미론적(Semantic) 검색만으로는 "문단 57", "손상차손 인식 요건" 같은 특수 용어 검색에서 정확도가 낮다. BM25(키워드 기반)와 Semantic 검색을 결합한 Hybrid Search를 사용한다.

```python
from langchain.retrievers import BM25Retriever, EnsembleRetriever

bm25 = BM25Retriever.from_documents(docs, k=3)
semantic = vectorstore.as_retriever(search_kwargs={"k": 3})

retriever = EnsembleRetriever(
    retrievers=[bm25, semantic],
    weights=[0.4, 0.6]   # 회계 용어 특성상 키워드 가중치 부여
)
```

### 5-2. 병렬 검색 (`app.py`)

3개 컬렉션을 순차 조회하면 응답 지연이 누적된다. `ThreadPoolExecutor`로 병렬 조회한다.

```python
from concurrent.futures import ThreadPoolExecutor

with ThreadPoolExecutor(max_workers=3) as ex:
    f_kifrs = ex.submit(kifrs_retriever.invoke, query)
    f_dart  = ex.submit(dart_retriever.invoke,  query)
    f_kam   = ex.submit(kam_retriever.invoke,   query)

ctx_kifrs = f_kifrs.result()
ctx_dart  = f_dart.result()
ctx_kam   = f_kam.result()
```

### 5-3. 구조화 출력 프롬프트 (`prompts.py`)

```
[시스템 프롬프트]
당신은 제약·바이오 산업 전문 회계처리 어시스턴트입니다.
다음 세 소스를 기반으로 답변을 아래 형식으로 작성하십시오.

## ① K-IFRS 기준
- 관련 기준서 및 문단 번호를 명시하여 인용할 것.
- 소스에 없는 내용은 추론하지 말 것.

## ② 실제 기업 처리 사례
- 기업명, 보고서 연도, 주석 번호를 출처로 명시할 것.
- 기업 간 처리 방식 차이가 있으면 비교하여 서술할 것.

## ③ 감사 관점 및 유의사항
- KAM 보고서 내용을 기반으로 핵심 감사 위험과 대응 방향을 서술할 것.

[소스]
K-IFRS: {ctx_kifrs}
기업 주석: {ctx_dart}
KAM 보고서: {ctx_kam}
```
